# 产品定位与路线图

本文是产品级决策的单一事实来源：定位、业务域、特色、路线图、开放问题。技术实现细节见 [development.md](development.md)，AI 协作约束见 [AGENTS.md](../AGENTS.md)。

## 定位

**ASSET//HUB 是面向独立游戏开发者的游戏素材一体化管理平台：在一个赛博朋克风格的纯前端控制台里，完成「发现 → 获取 → 管理 → 加工」素材的完整闭环。**

- 服务对象：独立游戏开发者，个人起步，架构兼容小团队（2-10 人）
- 形态：纯前端、本地优先（localStorage/IndexedDB），无后端阶段完整可用；数据层经 Repository 接口抽象，团队同步后端是替换实现而非重写
- 视觉：v22 cyber design token 为唯一基准，V17 只贡献信息架构与交互，视觉全部重皮

## 领域模型隔离

Site（发现域）与 Asset（管理域）是不同实体：数据模型、收藏、标签、存储键完全隔离。资产域存储键用 `ah_assets_*` 前缀（V17 曾直接用 `ah_favs`，与站点收藏撞车，已否决）。

## 关键架构决策

**本地存储只存元数据，二进制永不进 IndexedDB。**
资产库持久化层（IndexedDB）只存元数据 + File System Access 目录/文件句柄；二进制文件始终留在用户磁盘，应用只记"它在哪"。收益：容量、性能（启动速度）、备份三个问题同时消解；代价是 Chromium 系限定（Safari/Firefox 降级为只读元数据模式 + 手动重新关联文件）。句柄失效（目录被移动/改名）时 UI 引导重新关联，不静默丢失。

**差异化纪律（防做成「Web 版 Eagle」）。**
竞品（Eagle/Billfish 等桌面客户端）的护城河是系统级集成，Web 形态在桌面体验上打不赢。每个新功能提案必须通过三问之一：桌面客户端结构性做不到？游戏垂直场景独有（license/引擎导出）？发现域连通独有？三问都否就进 backlog 而非迭代。

**版本号规矩。**
原型稿版本号（v22 / V17）是历史文物，留在文件名里，不参与产品版本；产品对外只有 SemVer（`package.json`）；功能分支不带版本号。

## 开放问题

- 团队化的同步语义（离线编辑冲突）只定义到 Repository 异步接口层面：Asset 携带单调递增 `rev`，`put` 遇远端 `rev` 更高时返回冲突而非覆盖，UI 策略后置。具体同步协议留待后端阶段。
- V17 mock 数据含 unsplash 外链图与外部 demo URL，移植时替换为自有数据。
